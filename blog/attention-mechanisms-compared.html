Attention Mechanisms: A Practical Comparison

Flash Attention. Linear attention. Grouped-query attention. Multi-head. Every month there's a new paper claiming to make attention "more efficient." Here's how to choose based on your actual constraints.

The Standard (Multi-Head Attention)

Standard MHA computes full pairwise attention between all tokens. Complexity: O(n²) in sequence length.

When to use: You need maximum quality and have the compute budget. Most production models still use this or close variants.

Flash Attention

Not a different attention mechanism—it's an implementation that computes attention without materializing the full n×n matrix. Instead, it tiles through KV cache in SRAM.

Speedup: 2-4x over standard attention implementations. Memory: O(n) instead of O(n²).

When to use: Basically always for training. If your hardware supports it (A100, H100), use it. No quality tradeoff.

Grouped-Query Attention (GQA)

Used in Llama-2 70B and Mistral. Key-value heads are fewer than query heads.

Llama-2 70B: 8 key-value heads, 80 query heads. Reduces KV cache by 10x while maintaining quality.

When to use: Large models (70B+) where KV cache dominates memory. Tradeoff is minimal quality impact for massive memory savings.

Multi-Query Attention (MQA)

Extreme version of GQA: 1 key-value head. Used in Falcon and some smaller models.

More aggressive memory reduction, but can hurt quality on some tasks.

Linear Attention

Changes the attention computation to O(n) instead of O(n²). Theoretical advantage for long sequences.

Problem: Linear attention doesn't have the same inductive biases as softmax attention. Quality often suffers, especially for tasks requiring precise token-to-token relationships.

When to use: Very long sequences (>100K tokens) where standard attention is intractable. Models like Mamba and RetNet attempt to solve the quality problem with state space models.

Sliding Window Attention

Each token attends only to previous k tokens (e.g., Mistral's 4096 window). Combined with "spiking" to longer contexts when needed.

When to use: Mistral and similar architectures use this to get near-full-attention quality with reduced compute. Good for local pattern recognition tasks.

How ArchGene Evaluates Attention

We check attention mechanism compatibility with your:

  • Hidden dimension (some mechanisms require specific divisibility)
  • Head count (GQA/MQA require specific ratios)
  • Sequence length constraints
  • Hardware compatibility
Example: A client had d_model=7168 with GQA, wanting 8 KV heads. Problem: 7168 isn't divisible by 8 cleanly. They needed d_model=7168 or 8×k, but also wanted to use a specific CUDA kernel that required head_dim to be a power of 2. Multiple constraints interacted in ways that weren't obvious until we modeled them.

Recommendations

  • Small models (<10B): Full MHA + Flash Attention. Memory isn't the bottleneck.
  • Medium models (10-70B): GQA + Flash Attention. Standard for production.
  • Large models (70B+): MQA or heavy GQA. KV cache dominates.
  • Long context (>32K): Consider sliding window or linear attention variants.

The Point

Don't optimize attention until you need to. Start with Flash Attention—it's free performance. Only move to GQA/MQA when memory becomes the bottleneck. Don't use linear attention unless you have a specific long-context use case and are willing to experiment.
